# 日语歌词精读页 · 模板化流水线

一套可复用的产线：**换歌 = 换一份 song.json**。页面、样式、交互、校验脚本都不动。

- 成品形态：单文件 HTML，零外部依赖，双击即开，离线可用。
- 数据形态：一个 `*.song.json`（约 500–700 行），字段见 `references/song-schema.md`。
- 样板：`examples/brave-heart.song.json`（宮崎歩「brave heart」，22 卡 / 61 词 / 16 语法 / 12 题）就是完整可跑的参考。
  另有 `examples/brave-heart-lite.song.json`（8 行，继承母版，只关掉四个可选板块）和 `examples/_skeleton.song.json`（最小骨架）。

## 用户一句话进来，默认这么接

用户通常只会说一句「用那个模板做一首《Butterfly》」。这句话要能直接开工，所以下面这些值有明确默认，**不要反问一堆**：

| 项目 | 默认 | 用户怎么说会改 |
|---|---|---|
| 板块 | **4 块**：map / lines / vocab / grammar | 「要测验」「要七天计划」「八块全要」→ 开对应 `modules` |
| 难度 | N3 | 「N4」「N2」→ 调 `vocab[].lv` 分布与语法条难度 |
| 输出 | `~/code/me/jsongs/<slug>/{index.html,<slug>.song.json}` | 给了路径就用给的；同名文件存在时先问 |
| 配色 | 奶油纸底 + 橙/青 | 「换个蓝色系」→ 改 `assets/base.css` 顶部的 `--orange` / `--teal` |
| 封面 | **排版式封面**（纯 CSS，随歌名自动生成） | 「用我的封面图」→ 图片路径写进 `meta.cover`，build 自动内联 |
| 卡片量 | 16–24 张 | 「做细一点」→ 24+；「一页就够」→ 12 左右 |

**必须先确认的三种情况**（其余都自己判断）：

1. 歌名有重名（同名不同曲），或演唱者/出处对不上。
2. 找不到权威歌词来源，或两个来源差异大到影响讲解。
3. 这首歌明显不适合（饶舌、方言、通篇拟声词）——直接说"这首做不出教学价值"，并给替代建议。

**做完要主动报**：用了哪些板块、共几张卡/几个词/几条语法、文件路径、有没有触发版权裁剪，以及**有没有把它加进根目录合集页的 `SONGS` 数组**。

## 30 秒上手

本技能是**项目级**的，随 `~/code/me/jsongs` 一起走；下面的命令都在项目根目录执行。

```bash
SKILL=.workbuddy/skills/jp-song-study-page

# 1. 复制样板，改成新歌（数据源放在歌曲自己的目录里，自包含）
cp $SKILL/examples/brave-heart.song.json <slug>/<slug>.song.json

# 2. 只校验，不产出（改 JSON 时反复跑）
node $SKILL/scripts/build.js --check <slug>/<slug>.song.json

# 3. 出页面
node $SKILL/scripts/build.js <slug>/<slug>.song.json <slug>/index.html

# 4. 验收（无头 Chrome：交互 + 多断点溢出 + 截图）
node $SKILL/scripts/check.js <slug>/index.html --shots
```

`check.js` 依赖 `playwright-core`（本 skill 目录已装）。缺失时会自动降级为静态检查并提示。

### 项目目录约定

```
jsongs/
├── index.html              ← 合集索引页（曲目卡片列表）
├── brave-heart/            ← 一首歌一个目录
│   ├── index.html          ← 构建产物
│   └── brave-heart.song.json  ← 数据源，自包含
└── again/
    ├── index.html
    └── again.song.json
```

**新歌出页后还有一步**：在根 `index.html` 的 `SONGS` 数组里追加一条（slug / href / kicker / title / artist / year / tone / desc / scale）。否则新歌不会出现在合集页上。`tone` 取 `teal` 或 `rust`，同色系别连排。

歌曲页顶栏的「‹ 合集」默认指向 `../index.html`，正好是合集页；单独使用（没有合集页）时在 `meta.backHref` 写 `""` 关掉。

## 板块开关（先决定这一页做几块）

页面有 8 个板块，**核心四块永远保留**：学习地图 `map`、逐句精读 `lines`、核心词汇 `vocab`、语法图谱 `grammar`。

另外四块可选：听说训练 `listen`、歌词工作台 `studio`、填空测验 `quiz`、七天计划 `plan`。

在 song.json 里写：

```json
"modules": { "listen": false, "studio": false, "quiz": false, "plan": false }
```

`build.js` 会在**生成阶段**把这些 section 从 HTML 里裁掉，导航项、章节编号（01…0N）、顶部数据条全部自动跟随，不需要手工改模板。

- **四块精简版**（只讲歌词与词汇，适合分享/打印）：关掉后四块，数据条剩 3 项。
- **八块完整版**（自学用）：全开。
- 精简版不必重复写一份完整 JSON —— 用 `extends` 继承母版，只写差异：

```json
{
  "extends": "brave-heart.song.json",
  "modules": { "listen": false, "studio": false, "quiz": false, "plan": false },
  "stats": [ {"key":"lines","label":"精 读 句 数"}, {"key":"vocab","label":"核 心 词 汇"}, {"key":"grammar","label":"语 法 点"} ],
  "cta": { "primary": "开始逐句精读", "secondary": "先看语法图谱", "secondaryHref": "#grammar" }
}
```

`examples/brave-heart-lite.song.json` 就是这样 8 行的文件。**改内容只改母版**，lite 版自动跟随。

## 流程（顺序不要跳）

### 第 0 步 · 判断值不值得做

适合：语速中低速、咬字清晰、副歌有重复句式、语法点集中在 N4–N3。

不适合：饶舌/超快语速、大量古语或方言、歌词几乎全是拟声词。这种做出来只有"翻译"，没有"教学"。

一首歌做 16–24 张卡、50–70 个词、12–16 条语法、8–12 道题，是甜点区。少于这个量撑不起一页，多于这个量做不完也没人学。

### 第 1 步 · 核歌词（只核，不抄）

- **至少两个来源交叉核对**（官方歌词页 / 歌词站 / 作品 wiki）。日语歌词站的汉字和送假名经常互相矛盾，以官方或实体歌词本为准。
- 同时记下四项元信息：**作词 / 作曲・编曲 / 演唱 / 年份与出处**（哪部作品、OP 还是插入歌）。这些要进 `footer.note` 和 `meta.kicker`。
- **不要把整首歌词写进任何产物**。这一步的产出是"我确认过原文",不是"我有原文"。

### 第 2 步 · 切段落

听 2–3 遍，标出 Aメロ / Bメロ / サビ / 大サビ 的**时间点**（0:32 这种）。时间戳优先从歌词站的时间轴拿，比手数准。

每段给一个**功能词**：铺陈 / 推进 / 爆发 / 转折 / 加速 / 收束。功能词会出现在结构图的色块里，也是后面写卡片的语气依据。

写进 `segments`（key 用 a/b/s/c）和 `map.blocks`（weight 用该段秒数，页面按比例分配宽度）。

### 第 3 步 · 抽卡（16–24 张）

选句三条标准：

1. **一句一个语法点**。别在一张卡里塞两个。
2. **优先选"语法挤在一起"的句子**。比如 `なくせぬ` = 可能形 + 文言否定，一句能讲三层。
3. **必须有可讲的语感**。纯名词句（`青い星に`）单独成卡没有价值。

每张卡四个字段缺一不可：

| 字段 | 要求 |
|---|---|
| `jp` | 原文片段 + 注音，见下方写法 |
| `tr` | 中文，允许意译，但不许加原文没有的情绪 |
| `words` | 2–4 个词，`[汉字, 假名, 中文]` |
| `g` | 语法点，写"接续 + 这句话里怎么用" |
| `n` | 语感/唱法，**不许重复 `g` 的内容** |

**注音写法**：`漢字[かな]`，只给汉字注音，假名和助词不注。

```
逃[に]げたり あきらめるコトは 誰[だれ]も
生[い]き方[かた]に地図[ちず]なんかないけど
```

一张卡引用**不超过一行**，能半句就半句。

### 第 4 步 · 词表（50–70）

- **按歌词出现顺序**排，不按五十音。学习者是对着歌记的。
- `lv` 给**保守值**：拿不准就往低一级写。标高了会劝退，标低了没损失。
- 只收"这首歌里真的会挡路"的词。`する` `いる` `こと` 这种不收。
- 同一首歌里重复出现的词只收一次。

### 第 5 步 · 语法（12–16）

字段 `p / sub / form / mean / eg / warn`。

- `form` 是重点（接续），学习者九成的错都在接续上。
- `warn` 写**"会错在哪"**，不是百科定义。反例：「〜ば 是假定形」；正例：「口语里同义更常用 たら，ば 偏书面」。
- 同一句型只出现一次。`〜よう` 和 `〜う` 合成一条。

### 第 6 步 · 测验（8–12，可关）

**跳过条件**：`modules.quiz = false` 时这一段整块不做，`song.json` 里可以不写 `quiz`。

用 `【】` 标空，4 个选项，正确答案必须在 `opts` 里。三个禁忌，全部踩过：

1. **不能有第二解**。出过 `光がなくせ【】ように`，填 `ぬ` 和 `ない` 都对 → 题目作废。改考 `なく【せ】ぬ` 就唯一了。
2. **正确答案不要都放第一位**。页面运行时会随机打乱，但作者侧仍要打散，否则不利于人工审题。
3. **不考"歌词背没背"，考语法**。`描いた【夢】を` 这种题，`描いた星を` 也成立，属于坏题。改成 `描いた夢【】` 考宾格助词。

`why` 写"为什么是这个，为什么不是别的"。

### 第 7 步 · 写文案

固定段落（`map.why` 四条理由、`steps` 三步）每首歌都要重写，**不许套模板话术**。写不出四条理由，说明这首歌不该做。

如果开了 `listen` 模块，六张卡的骨架是（内容随歌变）：

1. 长音——这首歌里最长的那个长音词
2. 促音——这首歌里的促音词
3. 表记——有没有片假名强调、有没有特殊写法
4. 句尾——这首歌的句尾习惯（`から` 收尾 / 命令形收尾 / 疑问上升）
5. 训练法——给一个可执行的三档练习
6. 音域或节奏——副歌在哪、哪里换气

如果关了 `listen` / `plan`，`steps` 的第三步不要再说「去做测验」——改成「回到词表把没勾的过一遍」这类与该页实际内容对得上的动作。

### 第 8 步 · 构建 + 验收

```bash
node scripts/build.js  <song.json> <out/index.html>
node scripts/check.js  <out/index.html> --shots
```

验收必须全绿：

- [ ] 静态：无未替换占位符、关键容器齐全
- [ ] **板块数与 `modules` 配置一致，章节编号连续（01…0N），导航项数 == 板块数**
- [ ] 控制台无错误
- [ ] 顶部数据条项数正确、数值非 0
- [ ] 段落筛选能筛出子集
- [ ] 掌握度点击后进度变化
- [ ] 答题后正确项高亮 + 解析出现（仅当开了 quiz）
- [ ] 粘贴歌词能标注出词（仅当开了 studio）
- [ ] 计划勾选生效（仅当开了 plan）
- [ ] 390 / 768 / 1024 / 1440 四个宽度无横向溢出

再人工扫一遍 `preview/` 里的截图：重点看**注音有没有串行**、**长句有没有在小屏把词拆断**。

## 版权红线（不可协商）

- 页面**不出现完整歌词**，只引用短片段做语言分析。
- 单张卡片引用 ≤ 一行；整页引用总量控制在原词的 1/3 以内。
- 页面上不放"完整歌词下载""歌词全文"入口。需要全文的场景，用**歌词粘贴工作台**（用户自己贴，浏览器本地处理）。
- `footer.note` 必须保留标准版权句：

> 本页为日语学习用途的语言分析作品，不提供完整歌词。歌词著作权归作词 X、作曲 Y、演唱 Z 及相关权利方所有；页面仅引用极短片段用于语法与词汇讲解。请通过正版音源与官方歌词页对照收听。

- **封面**：默认用排版式封面（纯 CSS，无版权风险）。官方封面属于版权图片，**不要主动去图站抓图内嵌**；用户自己提供图片时才用，并内联进页面（个人学习用途）。

## 已知坑（都踩过，别重踩）

| 坑 | 现象 | 解法 |
|---|---|---|
| 媒体查询位置 | `@media` 里的规则被后面同权重的基础规则覆盖 | 媒体查询放到基础规则**之后**，或提高选择器权重（`.q .q-opts`） |
| 内联 flex-grow | 媒体查询里的 `flex` 简写压不过内联 `flex-grow` | 内联只写 `style="--w:28"`，CSS 用 `flex-grow:var(--w,1)` |
| `1fr` 的隐式最小宽 | 带 `nowrap` 的子元素把网格撑破，移动端横向溢出 | `minmax(0,1fr)` + 网格子项 `min-width:0` |
| 答案扎堆 | 12 题正确答案全在第 1 位 | 作者侧打散；`build.js` 会告警 |
| 一题多解 | 学习者选对了却被判错 | 换一个唯一解的空位 |
| 状态串歌 | 换歌后掌握度串了 | `render.js` 按 `meta.slug` 加 localStorage 前缀，**slug 必须每首歌不同** |

## 文件说明

```
assets/template.html   页面骨架，{{占位符}} 由 build 填充
assets/base.css        全部样式（改配色只动这里）
assets/render.js       渲染逻辑（改交互只动这里）
scripts/build.js       JSON → HTML，含字段校验
scripts/check.js       无头浏览器验收
examples/brave-heart.song.json   完整样板
references/song-schema.md        字段字典
references/editorial-guide.md    选词/选句/出题口径
```

改样式改 `assets/base.css`，改交互改 `assets/render.js`——**不要在生成的 index.html 上改**，下次 build 会覆盖。
