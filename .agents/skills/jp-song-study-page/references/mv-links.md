# 给导语挂 B 站视频链接（MV / 现场 / 完整版）

链接写在 `meta.lead` 末尾，模板直接当 HTML 渲染，所以只认这一种写法：

```html
<a href="https://www.bilibili.com/video/BVxxxxxxxxxx/" target="_blank" rel="noopener noreferrer">B站 MV ↗</a>
```

**不要手工试 BV 号**——同名不同曲、翻唱、谱例、AMV 混在一起，凭印象填十有八九是错的。

## 三条命令，各管一件事

```bash
SKILL=.agents/skills/jp-song-study-page

# 新歌：只在没有链接时写入
node $SKILL/scripts/mv.js <slug>/<slug>.song.json --write --only-missing

# 已有链接：只看它怎么评级、脚本首选是哪条，不动盘
node $SKILL/scripts/mv.js <slug>/<slug>.song.json

# 全站：现有链接有没有失效／明显错的
node $SKILL/scripts/mv.js --audit .
```

### 现有链接默认不会被覆盖

本仓库的链接**大部分是手工挑过、调整过的**，脚本没有资格静默改掉，所以：

| 情况 | `--write` 的行为 |
|---|---|
| `meta.lead` 里没有链接 | 直接写入首选 |
| 已有链接、首选正好一致 | 不写，打印 `✓ 一致，无需改动` |
| 已有链接、`--only-missing` | 不写，打印 `· 已有链接，--only-missing 不动它` |
| 已有链接、只有 `--write` | **不写**，提示加 `--force`，退出码 2 |
| 已有链接、`--write --force` | 覆盖 |

要换链接时的正常流程：先跑不带 `--write` 的那条，看它把候选按什么理由排序；确认后 `--write --force`，或直接 `--write --force --pick BV1xxx`。

| 参数 | 作用 |
|---|---|
| `--write` | 写盘；已有链接时还要再加 `--force` |
| `--only-missing` | 只在 `meta.lead` 没有链接时写，新歌专用 |
| `--force` | 明确允许覆盖现有链接 |
| `--pick BV1xxx` | 指定 BV 号（仍会调接口校验存在性、打印标题时长） |
| `--query "歌名 作者"` | 覆盖检索词，默认按歌名/作者/译名自动组合 |
| `--top N` | 打印前 N 条，默认 5；挑不出时用 `--top 10` |
| `--order totalrank\|click\|pubdate\|dm` | 排序方式，默认综合排序 |
| `--pages N` | 每条检索词翻几页（1–3，默认 2） |
| `--audit <root>` | 批量校验现有链接，不搜索 |
| `--backtest <root>` | 用现有链接当答案回测命中率，只读 |
| `--no-cache` | 忽略 `$TMPDIR/jp-song-mv-cache`（搜索结果缓存 12h，视频信息 7d） |

## 它怎么选

1. **检索**：用 5 条检索词各翻 2 页（每页 30）——`歌名 作者` / `歌名 官方 MV` / `歌名` /
   `中文译名` / `歌名 中文译名`，再补一遍 `歌名 作者` 的**按播放量排序**。去重后一般 180–230 条。
   单条检索词的池子只有 40 条，作者的候选常常压根不在里面——这是过去最大的漏检来源。
   「标题里只写中文译名」的稿子（《曾经我也想过一了百了》）只有靠译名那两条才搜得到。
2. **入场券**：标题必须对上歌名（整首标题拼起来 / 够长的分段 / `meta.aliases`），
   或者「UP 是作者本人号 **且** 标题里有作者名」。只对上歌名片段（`brave` 之于《brave heart》）
   也能进池，但 −1.2 分——这道闸就是用来挡住 YOASOBI《The Brave》这种同词不同曲的。
3. **淘汰**：只淘汰「内容根本不是这首歌」的——伴奏 / カラオケ / KTV / 翻唱 / cover / 歌ってみた /
   教学 / 解説 / 演奏 / 谱例 / 指弹 / 合集 / MMD / 8D / nightcore / remix / 空耳 等。
   **现场、acoustic、MAD、AI 修复、4K 重制都不淘汰**：作者的 42 条链接里 10 条是现场、2 条是 MAD、
   1 条是 acoustic 版，旧脚本把这些一律毙掉，等于先把正确答案删了再选。
4. **打分**（底分 = `log10(播放量)`）：

| 特征 | 权重 | 为什么 |
|---|---|---|
| 标题里写了作者名 | +2.0 | 最有效的单一信号，去掉它命中掉 5 首 |
| UP 是作者本人号 | +0.7 | 官方稿优先 |
| 厂牌 / 平台号（索尼、JVC、大家的音乐机…） | +0.5 | 次可信 |
| MV / PV / Official Video | +0.4 | |
| 中日字幕 | +0.4 | 学习页要能对照歌词 |
| 同一作者的其它曲目也选过这个 UP | +0.2 | 随手工调整自动更新 |
| 标题里有作品名（番名 / 剧名） | +0.2 | |
| 4K / Hi-Res / 修复 | +0.2 | |
| 现场 | +0.2 | |
| 只对上歌名片段 | −1.2 | 防《The Brave》之于《brave heart》 |
| 中文译名近似对上 | −0.5 | |
| 标题里压根没写歌名 | −2 | 只靠「作者本人号」兜底进来的同歌手其它投稿 |
| 短于 2:30 | −3 | 切片 |
| 长于 8:00 | −1 | 带解说或合集 |

5. **输出**：默认按分数打印前 5 条，每条带 `作者本人号 / 标题含作者 / MV / 中字 / 高画质 / 现场 / 你选过这个 UP`
   之类的标签，以及时长、播放量、UP 名。**看标签就能判断，不用点开视频。**

## 这套参数是怎么来的

拿仓库里 42 首**已经确认过的链接**当标准答案，把每条链接当正样本、同池其它候选当负样本，调权重：

| 指标 | 改造前 | 现在 |
|---|---|---|
| 你的选择出现在候选池里 | 32/42（76%） | **41/42（98%）** |
| 首选就是你的链接 | 13/42（31%） | **25/42（60%）** |
| 前 3 条里有你的链接 | 17/42（40%） | **30/42（71%）** |
| 前 5 条里有你的链接 | 19/42（45%） | **32/42（76%）** |

「改造前」的命中率是按同一批候选池算的（对旧打分器更有利），检索覆盖那行则是它自己的单条检索词。

随时可以自己复算——现有链接就是标准答案，`--backtest` 只读不写：

```bash
node $SKILL/scripts/mv.js --backtest .
```

调整过几条链接后重跑一次，一致率会变；加新歌后重跑，也能看出这套参数还准不准。

**剩下的 40% 差在哪**（属于口味，不是 bug）：同一首歌常有好几条都合格——
官方 MV 与 4K 现场、2018 现场与 2025 现场、官方稿与字幕组稿。
比如 `sparkle` 你选的是 2025 年那场、`rasen` 你选的是标注「第 5 话 ED」的字幕稿，
这类偏好没有可复现的文本特征，脚本学不到。所以它给的是**按你的口味排过序的候选**，不是替你拍板。

## 挑不出来的情况

| 现象 | 原因 | 怎么解 |
|---|---|---|
| `不在池` / 候选很少 | 歌名太常见、或标题全用中文译名 | `--query "歌名 歌手"` 换检索词；把译名补进 `meta.aliases` |
| 命中的是另一首歌 | 标题里有同名词 | `meta.aliases` 加区分词（如 `螺旋 RASEN`），或 `--pick` |
| 首选是现场，你想要录音室版 | 官方 MV 播放量远低于现场 | `--top 10` 看全，再 `--pick` |
| 搜索连续被风控 | 请求太密 | 等几分钟重跑；脚本每次自动重新签名，无需登录 |
| `code=-412` 反复出现 | 同上 | 删掉 `$TMPDIR/jp-song-mv-cache` 再试 |

## `meta.aliases`（可选字段）

给检索与匹配用的别名数组，不影响页面渲染，也不参与构建校验。适合补：中文译名、罗马字、繁体／简体差异、常见误写。
**它同时用于「检索词」和「歌名匹配」**——写进去的译名既能被搜到，也能对上标题只写中文的稿子。

```json
"meta": {
  "artist": "鈴木このみ",
  "aliases": ["铃木木乃美", "THERE IS A REASON", "NGNL0"]
}
```

脚本自带常见异体字归一（`宮/宫`、`歩/步`、`橋/桥`、`澤/沢/泽`、`龍/龙`、`聴/听` 等），
但**中文译名**（凛冽时雨、铃木木乃美）和**英文缩写**（NGNL0）归一不了，得靠 aliases。

## 选片的质量判据（人工复核用）

- **播放量**：几百到几千的基本是搬运、切片或 AMV；十万以上通常没大问题。
- **时长**：明显短于原曲 → 剪辑；明显长很多 → 带解说或合集。
- **UP 名**：作者本人号（`星野源`、`宇多田光`、`Ayase-YOASOBI`、`SPYAIR_OFFICIAL`）、
  厂牌号（`索尼音乐中国`、`JVC_Music`）、平台号（`大家的音乐机`）优先；个人搬运次之。
- **标题关键词**：`官方 MV / Official Video / 主題歌` 可信；`MAD / AMV / 纯享 / 试听 / 4K修复` 是二创或重制——
  作者本人接受这类稿子，但当同一首歌有官方稿时，优先官方。
