# 已知坑

分两类：**内容侧**（写 `song.json` 时会踩，`build.js` 多数会告警或报错）
和**模板侧**（只有改 `assets/base.css` / `assets/render.js` 才会踩，不报错，只在小屏上表现为溢出、错位）。

## 内容侧

| 坑 | 现象 | 解法 |
|---|---|---|
| 状态串歌 | 换歌后掌握度串了 | `render.js` 按 `meta.slug` 加 localStorage 前缀，**slug 必须每首歌不同** |
| 合集页没进度条 | 曲目卡上的掌握度不显示 | 合集页读 `jss.<SONGS[].slug>.mastery`，所以 `SONGS[].slug` 必须等于 `meta.slug`（目录名可以不同） |
| 合作曲歌手少算 | `打上花火` 只算给 DAOKO，米津玄師 的总数少一首，统计里也看不出错 | `SONGS` 里补 `artists: ['DAOKO', '米津玄師']`，只列真正演唱的人；作词作曲、角色名不列。规则见 SKILL.md「有合集页时」 |
| 板块数对不上 | 导航多一项或留下空节 | 正文只到语法图谱；默认缺少全文会报错；仅显式关闭全文时，导航与章节编号自动裁剪 |
| 逐句只改了标题 | 导航写「逐句精读」，`lines[].jp` 仍是词、半句或跨行拼接 | 运行 `build.js --check --strict-lines`；卡片必须去掉注音、忽略空白后与某条完整歌词完全相同 |
| 补卡时旧的半句还在 | 新建了整句卡，旧卡仍是半句；或两张碎片扩成同一行后校验报重复 | 先把旧卡扩成来源行。两张碎片对应同一行就合并，保留原来的讲解重点，不要两张并存 |
| 注音改了歌词里的汉字 | `降る` 对不上歌词的 `ふる`，`響き出した` 对不上 `響きだした`，`遠吠` 对不上 `遠吠え`，卡无法对应来源行 | 只给歌词里实际出现的汉字加注音。假名、送假名和标点保持原样 |
| 读音跟同歌已有卡不一致 | 这首歌的 `明日` 已读 `あす`，新卡写成 `あした`；`最中` 读成点心的 `もなか` | 先搜本文件已有的 `漢字[かな]`。`最中` 在「正当中」读 `さなか`，`掌` 读 `てのひら` |
| 范例仍是旧的短语卡 | 照抄 `examples/brave-heart.song.json` 的 `jp`，新页过不了 `--strict-lines` | 范例只看字段结构。逐句合同以 `lyrics.blocks[].lines` 为准 |
| 为避免重复漏掉变体 | 两行措辞不同却被当成同一句复用 | 仅完全相同或只有空白差异的行可以合并；删词、换词或语序变化的变体要分别建卡 |
| MV 链接指错歌 | 导语里的 B 站链接点开是别的歌、翻唱或 AMV | B 站综合排序第 1 条经常不是这首歌（`again YUI` 第一条是王极《Again》）。用 `scripts/mv.js` 搜，它按「歌名+作者」过滤打分；选中后仍要人工看一眼标题、UP、时长 |

## 模板侧（改样式或交互时看）

| 坑 | 现象 | 解法 |
|---|---|---|
| 媒体查询位置 | `@media` 里的规则被后面同权重的基础规则覆盖 | 媒体查询放到基础规则**之后**，或提高选择器权重（例如 `.g-row`） |
| `1fr` 的隐式最小宽 | 带 `nowrap` 的子元素把网格撑破，移动端横向溢出 | `minmax(0,1fr)` + 网格子项 `min-width:0` |
| 伪元素定位 | `::after` 用了 `inset:0` 之后再设 `right/top`，会被 `left:0` 拉回左上角 | 需要独立定位的装饰做成真实元素（如 `.cover-ring`），伪元素只留铺满的高光 |
| 封面搜不到原版 | 检索词带歌手仍返回翻唱／カラオケ／LIVE | `cover.js` 会打分并排除这些词；仍不对就 `--query "歌名 歌手"`，或 `--title` / `--artist` 覆盖字段。动画盘常要按歌手查专辑才命中（如 `brave heart`） |
| 日区 iTunes 根本没有这张盘 | 搜「前前前世 RADWIMPS」只返回 Aruvn 翻唱单曲 | 换美区找官方专辑图，用 `--artwork "<URL>"` 直接喂给 `cover.js`；它照样做补边、缩略图和 `meta.cover` |
| MV 搜到乐器翻奏 | `unravel` 搜出笛箫／吉他／TAB 版 | `mv.js` 的淘汰词表已含笛、箫、二胡、吉他、bass、弾いてみた、踊ってみた、歌い方、解説；新遇到的乐器名继续补进去 |
| 歌手译名对不上 | 标题写「凛冽时雨」，song.json 写「凛として時雨」，被判作者对不上 | 在 `meta.aliases` 加译名；aliases 同时参与歌名和作者匹配 |
| 封面不是方图 | build 警告宽高比、`object-fit:cover` 裁掉两侧 | `cover.js` 会自动用模糊底衬补成方形，主体不裁；手工换图时也照这个做法，不要硬裁 |
| Cover Art Archive 连不上 | `coverartarchive.org` 307 到 `archive.org` 后超时 | 沙箱代理常拦 archive.org，换 iTunes API；CAA 只适合 iTunes 查不到的冷门盘 |
| `background-clip:text` 与紧行高 | 大标题字形顶部／底部被齐齐削掉一条，看起来像被别的元素遮住 | 行高（`.84`）小于字形高度时，字形伸出元素的背景绘制盒；渐变只在盒内绘制，盒外就是透明。给标题加 `padding-block:.2em` 撑大绘制盒，再用 `margin-top:calc(.9rem - .2em)` 和副标题的 `margin-top:calc(1.05rem - .14em)` 抵消，视觉节奏不变。自查：`scrollHeight === clientHeight` 才算字形完整落在盒内 |
