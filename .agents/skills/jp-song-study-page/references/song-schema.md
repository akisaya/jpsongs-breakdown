# song.json 字段字典

一份 `song.json` 就是一个页面。正文章节为学习重点、完整歌词（默认必填）、逐句精读、词汇表、语法图谱。语法图谱是最后一节。

```bash
node scripts/build.js --check --strict-lines song.json   # 新建/维护逐句页时用这个
```

## 骨架

```json
{
  "extends": "另一份.json",   // 可选：继承母版，只写差异
  "modules": { "lyrics": true },  // 默认值，可省略整个 modules

  "meta":   { ... },          // 必填
  "stats":  [ 3 项 ],       // 顶部数据条
  "cta":    { ... },          // 两个按钮
  "nav":    [ 默认 5 项 ],       // 章节导航
  "map":    { ... },          // 学习地图
  "steps":  [ 3 项 ],
  "sec":    { map, lyrics, lines, vocab, grammar },  // 必填
  "lyrics": { "blocks": [...] },  // 默认必填：完整歌词
  "lines":  [ 卡片 ],          // 必填
  "vocab":  [ 词 ],            // 必填
  "grammar":[ 语法 ],          // 必填
  "footer": { "title", "note", "meta": [3 行] }
}
```

## modules（可选）

默认五块 `map / lyrics / lines / vocab / grammar`。完整歌词默认必填；只有用户明确要求不要全文时，才通过 `"modules": {"lyrics": false}` 关闭。默认缺少 `lyrics.blocks`、空段落或空歌词行会构建失败。
导航和章节编号自动跟随，正文始终结束于语法图谱。

## extends（可选）

```json
{ "extends": "brave-heart.song.json", "meta": { "level": "N3 上下" } }
```

- 路径**相对于当前文件**，最多 5 层。
- 合并规则：对象递归合并，**数组整体替换**（所以要改 `stats` 就得写全数组）。
- 典型用法：继承同一首歌的基础数据，仅调整标题、难度文案或学习步骤。

## meta（必填）

| 字段 | 说明 |
|---|---|
| `slug` | **必须每首歌不同**。用于 localStorage 命名空间，重复会导致掌握度串歌。小写短横线，如 `brave-heart` |
| `pageTitle` | `<title>` 全文 |
| `description` | meta description，120 字内 |
| `kicker` | 标题上方那行小字，格式「作品名 · Insert Song · 年份」 |
| `titleLine1` / `titleLine2` | 大标题拆两行。只有一行时 `titleLine2` 给 `""` |
| `artist` | 演唱者 |
| `subtitle` | 通常 `歌詞精読` |
| `level` | 大致难度档位，会显示在封面右下角，如 `N3 上下`、`N3–N2` |
| `lead` | **允许 HTML**。首屏导语，一到两句，说清"为什么拿这首入门"。末尾通常挂一条 B 站链接，由 `scripts/mv.js` 写入，见 `references/mv-links.md` |
| `aliases` | 可选。给 `mv.js` 检索用的别名数组（中文译名、罗马字、常见误写），不影响渲染，也不参与校验 |
| `badges` | 4 个徽章。**第一个**会渲染成等级色（橙色），其余是圆点样式 |
| `discLabel` / `discSub` | CD 中心的字，通常年份 + `single`；同时作为排版封面的年份 |
| `cover` | 首屏封面，三种写法见下。**不填 = 排版式封面**；推荐先跑 `scripts/cover.js` 自动生成 |
| `coverTag` | 排版封面左上角的小字，默认 `Single` |
| `coverAlt` | 图片封面的 alt，不填则用「歌名 封面」 |
| `backHref` | 顶栏「‹ 合集」的链接。不填默认 `../index.html`（对应 `<slug>/index.html` 的结构）；显式写 `""` 则不显示该入口 |
| `backLabel` | 返回链接的文案，默认 `合集` |

### 封面（meta.cover）

首屏默认渲染一张**排版式封面**（纯 CSS + 文字，无图片文件）：深青底、数码网格、歌名用衬线斜体，顶部 `SINGLE / 年份`，底部 `歌詞精読 / N3`。信息全部来自 `meta`，换歌自动变。

**默认改用官方封面**：跑一次 `node scripts/cover.js <song.json>`。脚本按「歌名 + 歌手」检索 iTunes，打分挑原版单曲（排除 LIVE／翻唱／カラオケ／オルゴール／inst），取 1000px 图，方图缩到 800×800，非方图用模糊底衬补成方形，写入 `covers/cover.jpg`、另出一张 320px 的 `covers/thumb.jpg`（合集页卡片用），并把 `meta.cover` 指过去。已有封面会跳过，`--force` 重抓，`--query "歌名 歌手"` 手动指定检索词，`--dry-run` 只看选哪张。

日区 iTunes 查不到某些动画盘，或只返回翻唱（例：RADWIMPS「前前前世」日区只有 Aruvn 的翻唱单曲）。这时从美区 iTunes 或其他官方渠道拿到图后直接喂给脚本：
`node scripts/cover.js <song.json> --force --artwork "<图片URL>"`，后面的补边、缩略图、`meta.cover` 流程照常。拿到图后看一眼是不是原唱官方图。

| 写法 | 效果 |
|---|---|
| 不填 | 排版式封面（不跑 `cover.js` 时的兜底，零文件） |
| `"disc"` | 回到旧版的 CD 唱片图形 |
| `"covers/cover.jpg"` | `cover.js` 生成的封面。相对路径**相对于该 song.json**，build 时自动转 base64 内联，产物仍是单文件 |
| `"https://..."` | 外链图片（不内联，页面需要联网） |

图片建议：正方形，≥600×600，压到 300KB 以内（超过 600KB 会告警）。`build.js` 会自动识别 jpg / png / webp / gif / svg，并读取实际像素尺寸，两种情况会给出提醒：

- **不是正方形**（宽高比偏离 1 超过 6%）——页面按方形 `object-fit: cover` 裁切，会切掉长边两侧，提醒你确认主体居中；
- **短边 < 600px**——页面上会放大到约 378px 显示，清晰度不够。

封面版权归原权利方。个人学习项目直接用 `cover.js` 取来的官方图即可，页面底部 `footer.note` 的版权句照旧保留；若用户明确要求公开发布且不愿担图片风险，再把 `meta.cover` 清空、删掉 `covers/`，回到排版式封面。

## stats

3 项，`label` 是文案，数字由脚本按 `key` 自动填。项数会决定数据条的列数。

```json
"stats": [
  {"key":"lines","label":"精 读 句 数"},
  {"key":"vocab","label":"核 心 词 汇"},
  {"key":"grammar","label":"语 法 点"}
]
```

- `key` 只能是 `lines / vocab / grammar`。
- 窄屏两列，第三项自动跨两列。

## cta

```json
"cta": { "primary": "开始逐句精读", "secondary": "先看语法图谱", "secondaryHref": "#grammar" }
```

`secondaryHref` 必须指向页面上真实存在的锚点，默认 `#grammar`。

## map

> 章节本身的编号/标题/日文小标/导语统一放在 `sec.map` 里，**不要**在 `map` 里再写一遍。

| 字段 | 说明 |
|---|---|
| `whyTitle` / `whySub` | 学习理由的标题与副标 |
| `why` | 4 条 `{t, d}`，说明"为什么适合 N3" |

学习地图只展示学习理由与三步学习法，不需要曲式分类、结构时间轴或配色数据。

## steps

```json
"steps": [{"k":"STEP 01","t":"先听，别查词","d":"..."}]
```

固定 3 条：听 → 精读 → 回看词汇或语法例句。

## lyrics（默认必填）

完整歌词，按来源的空行分段，保留原文顺序。默认必须提供非空 `blocks`，每段必须有非空歌词行。只有明确设置 `modules.lyrics = false` 时才省略；缺数据不会自动关闭。

```json
"lyrics": {
  "foot": "点击行末的喇叭可以朗读。注音与逐句讲解在下一节「逐句精读」。",
  "blocks": [
    { "lines": [
        "逃げたりあきらめるコトは 誰も",
        "一瞬あればできるから 歩き続けよう"
    ]},
    { "lines": ["どんな願いも 嘘じゃない"] }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `lines` | 每行一句，日文原文。**不要写注音括号**——这一块是给人对着听的，标了反而看不清 |
| `foot` | 区块下方的一行提示 |

页面自动编号「段落 01 / 02…」，无需填写段落名称、类型、颜色或时间戳。
歌词在一张连续纸面中展示，每行末尾有原生朗读按钮，支持鼠标与键盘。

## sec（必填）

默认 5 个章节的标题区；明确省略全文时为 4 个章节，字段统一 `num / title / jp / lead`：

```
sec.map / sec.lyrics / sec.lines / sec.vocab / sec.grammar
```

`num` 从 `01` 顺排；插入或裁掉板块时**不用手改**，运行时会按实际顺序重排。
`jp` 用平假名写章节名的读法，全角空格分词。

## lines（必填，通常 16–24 张）

| 字段 | 说明 |
|---|---|
| `jp` | **一条完整歌词来源行** + `漢字[かな]` 注音 |
| `tr` | 中文 |
| `words` | `[[汉字, 假名, 中文], ...]`，2–4 组 |
| `g` | **允许 HTML**（`<b>` 包句型）。语法说明 |
| `n` | 语感 / 唱法备注，纯文本。**不要重复 g** |

注音只标汉字，假名和助词不标。括号必须是半角 `[ ]`。

**逐句合同**：把 `jp` 的 `漢字[かな]` 去掉、忽略空白后，结果必须与
`lyrics.blocks[].lines` 中某一条完全相同。不能只放一个词、半句，或跨行拼接。
同一句有多个语法点，也保留完整行，只选一个写进 `g`。完全相同、仅空白不同的歌词行只保留一张卡；
用词、省略或语序不同的变体是不同的来源行。不同行超过 24 条时可以超过 24 张卡，完整性优先。

运行 `--strict-lines` 时，构建器还会强制：

- `nav[].id="lines"` 的标签必须是「逐句精读」；
- `sec.lines.title` 与 `cta.primary` 必须明确包含「逐句精读」；
- 每张卡必须对应完整歌词行，且不能有两张卡指向同一条歌词。

校验会额外提醒尚未建卡的歌词行。完全重复的歌词可以复用讲解；如果出现不同变体，应分别建卡。

```
逃[に]げたり あきらめるコトは 誰[だれ]も
生[い]き方[かた]に地図[ちず]なんかないけど
```

## vocab（必填，50–70）

```json
{"k":"逃げる","r":"にげる","p":"動I","cn":"逃跑；逃避","lv":"N4"}
```

- `p` 词性：`名 / 動I / 動II / 動III / 形I / 形II / 副 / 代 / 名/形II`。
- `lv` 只能是 `N1`–`N5`，给保守值。
- `k` 写词典中的辞书形，歌词中的活用形式在精读卡里说明。

## grammar（必填，12–16）

```json
{
  "p": "〜にしか〜ない",
  "sub": "唯一限定",
  "form": "名詞 ＋ にしか ＋ 否定形",
  "mean": "只有…才…",
  "eg": "君にしかできないコトがある",
  "examples": [
    {"jp":"この仕事[しごと]は彼[かれ]にしかできない。","tr":"这项工作只有他能做。"},
    {"jp":"この秘密[ひみつ]は君[きみ]にしか話[はな]せない。","tr":"这个秘密我只能告诉你。"}
  ],
  "warn": "しか必须与否定呼应；に保留原句的格关系。"
}
```

- `eg` 保留歌里的原句（不带注音）。
- `examples` **必填 2–3 项**，每项包含日文 `jp`（汉字用 `漢字[かな]` 注音）和中文 `tr`。
- 例句独立于歌词原句，使用不同语境说明对应句型。并列介绍多个用法时，覆盖这些用法。
- `warn` 写易错点。页面顺序：接续 → 意思 → 原句 → 例句 → 注意。
- 构建会校验例句数量、必填字段、注音括号与重复句子。

## footer

```json
"footer": {
  "title": "brave heart",
  "note": "版权句，模板见 editorial-guide.md 的版权一节",
  "meta": ["DIGIMON ADVENTURE", "歌詞精読ノート", "JLPT N3"]
}
```

`meta` 是数组，渲染成右对齐的三行。

## 渲染约定（改 render.js 时看）

- `{{a.b.c}}` 由 build.js 用点路径取值；数组值默认 `join('<br>')`；缺字段直接构建失败。
- 富文本字段（`meta.lead`、`lines[].g`、`lines[].n`）**原样插入**，不转义——作者要自己保证只有安全标签。
- 其余字段一律 `escapeHtml`；例句日文先转义，再把注音转成 ruby。
- 卡片与词的渲染顺序完全按数组顺序，不做排序。
